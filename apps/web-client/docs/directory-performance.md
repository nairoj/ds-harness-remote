# 会话目录加载耗时排查

2026-10-27，只读请求 HIH-D-23754，DSH 0.2.0-rc.2、Remote 0.5.14。未修改会话、配置或运行中的程序。

## 实测

- 共 639 个会话，目录响应约 11,383,863 字节（11.4 MB）。
- 本机 HTTP 读取成功：3,789 / 3,526 ms；复测 3,108 / 2,896 ms。
- 独立加密 Remote 请求：53,142 ms，复现原先约 53 秒的等待。
- 浏览器在原生页面并发加载期间的一次额外目录请求约 100,127 ms；该值有并发干扰，不作为独立传输基准。
- 小请求（能力探测、工作区流开关）约 22–27 ms。

## 独立 Remote 请求的阶段

1. 普通 harness.remote.call 约 2,780 ms 后返回 RESPONSE_TOO_LARGE。
2. 客户端改走 transfer：open、请求 chunk 合计约 49 ms；commit 约 2,419 ms。
3. 响应分成 22 块，顺序调用 harness.remote.transfer.read，每块原始数据最多 512 KiB，完整块的 Base64 JSON 约 699 KB；大多数每块约 2.2 秒。
4. 收齐后解码 JSON，再关闭 transfer。

普通调用超限后会再次以 transfer 提交相同只读请求，因此重复产生一次目录响应。这里是上游 RemoteTypertGateway 自带的回退逻辑。

## 响应为何大

DSH ApiSessionList.projectionsFor 把每个会话已有的所有投影值带进目录；投影是供界面各区域使用的派生数据，并不限于目录所需字段。

| 投影字段 | 合计 JSON 字节 | 含义 |
|---|---:|---|
| contextHeaders | 7,265,584 | dsh-context 插件记录的请求头阶段元数据，包括工具名和 token 估算；不是完整系统提示词正文 |
| turnOutline | 1,812,701 | 各轮次的用户提问与最终回复的截断预览 |
| contextTimeline | 741,678 | dsh-context 的上下文时间线数据 |

上述三项约占响应的 86%。此前“目录只是摘要”的表述过于简化：没有下载完整消息日志，但确实附带了轮次文本预览与大量面板元数据。

## 结论与后续方向

主要等待发生在大响应的分块传输，电脑读取仍有约 3 秒成本。没有证据表明是基础网络往返延迟高；也未进一步分解每块传输中的带宽、服务端限速和加解密成本。

优先方向是电脑端提供轻量目录，仅返回列表所需字段，打开会话后再按需取详情投影；在网页收到数据后删字段不能减少已发生的传输。分页应在电脑端读取/生成阶段生效。此次只定位，没有实施这些行为变更。
